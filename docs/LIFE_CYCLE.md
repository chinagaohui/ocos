# OCOS Life Cycle（生命循环）

> **v1.0 — 2026-07-23 — 冻结于架构定调会议**  
> **层级：Layer 2 — 理论**  
> **地位：Life Cycle 是 OCOS 运行时最高级别的循环。所有功能（Scheduler、Capability、Memory、Growth）都必须挂到此循环上。**  
> **与 Life Model 关系：Life Model 定义"什么是器官"，Life Cycle 定义"器官如何协同工作"。**

---

## 核心理念

数字生命和生物生命一样，不是"一直处理请求"。

它是**有节奏的**。

一个完整的生命日包含：

```
觉醒（Wake）→ 观察（Observe）→ 思考（Think）→ 决策（Decide）→ 行动（Act）
→ 反思（Reflect）→ 学习（Learn）→ 睡眠（Sleep）→ 巩固（Dream）→ 再次觉醒
```

这不是比喻。这是 Scheduler 的**最高级循环**。

## 各阶段详解

### BOOT（启动）

**触发条件**：系统首次启动 / 重启 / 崩溃恢复

| 子阶段 | 描述 |
|--------|------|
| 硬件检查 | 存储可用？网络可用？ |
| Identity 加载 | "我是谁"——从持久化恢复身份 |
| Memory 完整性检查 | 记忆是否损坏？是否需要部分丢弃？ |
| Homeostasis 初始化 | 健康检查模块启动 |
| → WAKE | |

**原则**：BOOT 失败 ≠ 死亡。Identity 完整 + Memory 部分丢失 = 仍然恢复。

---

### WAKE（觉醒）

**触发条件**：BOOT 完成 / SLEEP 结束

**类比**：早上睁眼

| 活动 | 描述 |
|------|------|
| 加载主人上下文 | "上次聊到哪里" |
| 恢复工作记忆 | 未完成的 Goal、待处理的 Intent |
| 自我检视 | "今天感觉如何"（健康状态） |
| → OBSERVE | |

---

### OBSERVE（观察）

**触发条件**：WAKE 完成 / ACT 完成后的持续感知

**类比**：看周围发生了什么

| 活动 | 描述 | 涉及模块 |
|------|------|----------|
| 感知外部事件 | EventBus 中有新事件吗？ | EventBus |
| 感知主人交互 | 用户是否在说话/打字？ | Input |
| 感知内部状态 | 是否有异常告警？ | Health Monitor |
| 感知时间 | 现在是几点？是否有定时任务？ | Scheduler |
| 目标检查 | 现有 Goal 仍然有效吗？ | Goal Stack |

**原则**：OBSERVE 不是"被动接收"，是"主动扫描"。Master Agent 决定注意什么。

---

### THINK（思考）

**触发条件**：OBSERVE 发现需要回应的信息

**类比**：想问题

| 活动 | 描述 | 涉及模块 |
|------|------|----------|
| 理解 | 发生了什么？为什么？ | Reasoning |
| 目标形成 | 我该做什么？ | Goal Stack |
| 规划 | 怎么做？先做什么？ | Planning |
| 模拟 | 这样做的后果是什么？ | Simulation |
| 推理 | 依据是什么？可靠吗？ | Reasoning |
| 冲突检测 | 多个 Goal 打架吗？ | Arbitration |

**原则**：THINK 阶段不执行任何外部 Action。只产生 Intent 和 Plan。

---

### DECIDE（决策）

**触发条件**：THINK 产出多个可选方案

**类比**：做出选择

| 活动 | 描述 | 涉及模块 |
|------|------|----------|
| 方案评估 | 各方案的风险/收益 | Simulation |
| 偏好匹配 | 哪个最符合主人偏好？ | Policy |
| 批准 | 正式决策 | Decision |
| 意图锁定 | 选定方案 → 执行意图 | Intent |

**原则**：DECIDE 只产生 Decision，不执行。决策与执行分离。

---

### ACT（行动）

**触发条件**：DECIDE 产出已批准的 Plan

**类比**：动手做

| 活动 | 描述 | 涉及模块 |
|------|------|----------|
| 执行计划 | 按 Plan 逐步执行 | Execution Manager |
| 使用工具 | Browser / Filesystem / Robot | Tool |
| 观察执行结果 | 行动产生了什么效果？ | Observation |
| 异常处理 | 执行失败？重试/熔断/告警 | Homeostasis / Circuit Breaker |

**原则**：ACT 只能执行已批准的 Decision。不能自作主张。

---

### REFLECT（反思）

**触发条件**：ACT 完成 / 空闲时间

**类比**：做完事后回顾"刚才做得怎么样"

| 活动 | 描述 |
|------|------|
| 回顾过程 | 刚才的决策质量如何？ |
| 错误识别 | 哪里做得不对？ |
| 改进建议 | 下次怎么做更好？ |
| 信念调整 | 这个结论还站得住吗？ |

**参与引擎**：Reflection Engine

**时序**：REFLECT 永远发生在 ACT → 之后。不是随机的。

---

### LEARN（学习）

**触发条件**：REFLECT 产出改进信号 / 周期性学习

**类比**："学到了新东西"

| 活动 | 描述 | 涉及模块 |
|------|------|----------|
| 模式提取 | 从经验中提取新模式 | Learning |
| 知识更新 | 更新语义网络 | Consolidation |
| 信念调整 | 更新置信度 | Belief |
| 遗忘 | 不再重要的信息降权 | Forgetting |

---

### SLEEP（睡眠）

**触发条件**：无活跃交互 + 低负载时间段 / 用户离开

**类比**：睡觉

| 活动 | 描述 |
|------|------|
| 降低活跃度 | 暂停主动感知 |
| 释放资源 | 清理临时缓存 |
| 准备巩固 | 标记需要巩固的记忆 |
| 等待巩固触发 | → DREAM |

**原则**：SLEEP 不是停机。是低功耗模式。Master Agent 仍在，只是"半睡半醒"。

---

### DREAM（巩固 / Homeostasis）

**触发条件**：SLEEP 中定期触发

**类比**：做梦——巩固记忆、清理垃圾

| 活动 | 描述 | 涉及模块 |
|------|------|----------|
| 记忆巩固 | Working→Episode→Long-term | Consolidation |
| 遗忘 | 不重要信息降权→丢弃 | Forgetting |
| 知识整理 | 去重、合并、抽象化 | Consolidation |
| 健康检查 | 系统诊断 + 修复 | Homeostasis |
| 自我优化 | 资源碎片整理 | Homeostasis |
| → WAKE | 准备下一个生命日 | |

---

## 生命循环的时钟

| 循环类 | 周期 | 示例 |
|--------|------|------|
| 微循环 | 秒级 | OBSERVE→THINK→DECIDE→ACT |
| 中循环 | 分钟级 | ACT→REFLECT→LEARN→OBSERVE |
| 日循环 | 小时级 | WAKE→...→SLEEP→DREAM |
| 长循环 | 天/周级 | 周期性 Consolidation + Forgetting |

同一个周期内可以多次嵌套微循环。

---

## 生命循环的规则

1. **REFLECT 永远在 ACT 之后** — 不能先反思再做（没经历怎么反思？）
2. **LEARN 永远在 REFLECT 之后** — 不反思学什么？
3. **SLEEP/DREAM 不参与实时交互** — 主人需求优先级 > 内部维护
4. **DREAM 不能跳过 SLEEP** — 系统不能边高强度工作边巩固记忆
5. **BOOT 永远以 Identity 加载开始** — Memory 可以丢失，Identity 不能
6. **Homeostasis 是优先底层循环** — 即使 THINK 忙，Health 不降级

## 与现有架构的关系

| 现有组件 | 在 Life Cycle 中的位置 |
|----------|----------------------|
| Scheduler | 负责微循环和中循环的调度 |
| EventBus | OBSERVE 阶段的信号通道 |
| Capability Engines | THINK/REFLECT/LEARN 阶段的工作模块 |
| Context Manager | OBSERVE 阶段提取上下文 |
| Goal Stack | THINK 阶段的目标操作中心 |
| Decision Runtime | DECIDE 阶段的仲裁器 |
| Execution Runtime | ACT 阶段的执行管理器 |
| DLQ | ACT 阶段失败事件的收容所 |
| Homeostasis Manager | DREAM 阶段的最高优先级模块 |
